## 场景

- 订单服务：ThinkPHP （生产者，创建订单，发送 MQ）
- 库存服务：Laravel （消费者 1，扣减库存）
- 支付服务：Hyperf（消费者 2，处理支付）

> 使用 **RabbitMQ + 本地消息表（可靠消息最终一致性方案）**，这是微服务跨多框架最稳妥方案，适合你现在多框架异构项目，避免 TCC 侵入业务。

## 核心流程：

1. 订单库【本地消息表】+ 订单业务在**同一个数据库事务**写入：创建订单 + 写入消息记录（状态 = 待发送）
2. 订单服务异步把消息推送到 RabbitMQ，推送成功修改消息状态为已发送；推送失败定时任务重试
3. 库存服务消费消息：开启事务，扣库存；业务成功提交，手动 ack；失败 nack，消息重回队列重试
4. 支付服务消费消息：开启事务，创建支付单；业务成功提交，手动 ack；失败 nack
5. 兜底：定时任务扫描本地消息表，补发长时间未发送 / 未确认的消息；消费端做幂等（消息唯一 ID）

## 数据库 SQL（带注释）

### 订单库（ThinkPHP）表

业务表：`order` 订单主表

 本地消息表：`local_message` 【订单服务生产者消息表】 

幂等表：`order_consume_idempotent` 【订单消费补偿消息幂等】

```sql
-- 订单主表
CREATE TABLE `order` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '订单主键自增ID',
  `order_no` VARCHAR(64) NOT NULL COMMENT '订单编号，全局唯一',
  `user_id` BIGINT NOT NULL COMMENT '下单用户ID',
  `goods_id` BIGINT NOT NULL COMMENT '商品ID',
  `buy_num` INT NOT NULL COMMENT '购买数量',
  `amount` DECIMAL(10,2) NOT NULL COMMENT '订单总金额',
  `status` TINYINT NOT NULL DEFAULT 0 COMMENT '订单状态：0待支付，1已支付，2已取消',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_order_no` (`order_no`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';

-- ===================== 订单本地消息表【订单服务作为生产者，第一张本地消息表】=====================
CREATE TABLE `local_message` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '消息自增主键',
  `msg_id` VARCHAR(64) NOT NULL COMMENT '全局唯一消息ID，UUID，幂等标识',
  `order_no` VARCHAR(64) NOT NULL COMMENT '关联订单号',
  `exchange` VARCHAR(64) NOT NULL COMMENT 'RabbitMQ交换机名称',
  `routing_key` VARCHAR(64) NOT NULL COMMENT 'RabbitMQ路由key',
  `msg_content` TEXT NOT NULL COMMENT '消息体，JSON字符串',
  `status` TINYINT NOT NULL DEFAULT 0 COMMENT '消息状态：0待发送，1发送成功，2发送失败',
  `retry_count` INT NOT NULL DEFAULT 0 COMMENT '已重试次数，最多5次',
  `next_retry_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '下次重试时间，定时任务以此扫描',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '记录创建时间',
  `update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '记录更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_msg_id` (`msg_id`),
  KEY `idx_status_retry` (`status`, `next_retry_time`) COMMENT '定时任务查询索引'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单服务本地消息表';

-- 订单消费幂等表（订单消费库存失败、支付补偿消息用）
CREATE TABLE `order_consume_idempotent` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键',
  `msg_id` VARCHAR(64) NOT NULL COMMENT 'MQ消息唯一id',
  `order_no` VARCHAR(64) NOT NULL COMMENT '订单号',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_msg_id` (`msg_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单消费幂等表';

```

### 补充 区分两个完全不同的场景

#### **生产者（发消息）：本地消息表 `xxx_local_message`**

- 谁发消息，谁在自己库写这条记录
- `msg_id`：本次要发送出去的消息 ID
- status=1：**这条消息投递成功**
- 用途：保证业务操作和消息写入原子性 + 定时补发

> 这是【我发给别人】的记录

#### **消费者（收消息）：幂等控制**

- 收到别人投递过来的 MQ 消息，消息自带 `msg_id`
- 要记录：**这个 msg_id 我已经处理完了，不要再重复处理**

> 这是【别人发给我】的记录

### 订单服务 ThinkPHP7

#### 模型

`app/model/LocalMessage.php`

```php
<?php
namespace app\model;
use think\Model;

/**
 * 订单服务【本地消息表模型】
 * 生产者消息表：下单时，在事务内写入待投递MQ消息，用于保证消息可靠投递
 * 定时任务扫描本表重试发送失败消息
 */
class LocalMessage extends Model
{
    /**
     * 表名
     */
    protected $table = 'local_message';

    /**
     * 自动维护创建、更新时间
     */
    protected $autoWriteTimestamp = true;

    /**
     * 消息状态常量
     */
    /**
     * STATUS_WAIT：0 待发送，事务写入消息，还未投递MQ或者投递失败等待重试
     */
    const STATUS_WAIT = 0;
    /**
     * STATUS_SEND_SUCCESS：1 发送成功，消息成功投递到RabbitMQ
     */
    const STATUS_SEND_SUCCESS = 1;
    /**
     * STATUS_SEND_FAIL：2 发送失败，投递异常，等待定时任务重试
     */
    const STATUS_SEND_FAIL = 2;
}
```

`app/model/IdempotentRecord.php`

```php
<?php
namespace app\model;
use think\Model;

/**
 * 订单服务消费幂等记录表
 * 消费外部MQ消息时使用：收到消息，先判断msg_id是否存在本表，存在直接丢弃，防止重复消费
 * 每条MQ消息唯一msg_id，唯一索引保证不会重复写入
 */
class IdempotentRecord extends Model
{
    /**
     * 表名
     */
    protected $table = 'idempotent_record';

    /**
     * 自动写入创建时间
     */
    protected $autoWriteTimestamp = true;
    /**
     * 不需要update_time字段
     */
    protected $createTime = 'create_time';
    protected $updateTime = false;
}
```
