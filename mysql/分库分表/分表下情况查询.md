##  分表之后做“范围查询”

分表后做范围查询（18-29 岁）完整方案

你现在是**按用户 ID / 哈希分表**（user_0 ~ user_3），这种分表方式**天然不支持跨表范围查询**（年龄、时间、区间都算）

现在的分表规则：

`user_0`、`user_1`、`user_2`、`user_3` = **按用户 ID 取模 / 哈希分片**

特点：

- 同一个用户 → 固定在一张表
- **年龄相同的用户，会随机散落在所有分表里**

所以：

**直接查单张表查不全，必须查所有表**

### 方案 1：最简单 → 全表扫描 + 合并（小数据量首选）

适用场景

数据量不大（单表 < 100w）、并发不高、快速上线

实现逻辑（伪代码）

1. 遍历所有分表：user_0、user_1、user_2、user_3
2. 每张表都执行 `age between 18 and 29`
3. 代码层合并结果、排序、分页

SQL 示例（单表）

```sql
SELECT * FROM user_0 WHERE age BETWEEN 18 AND 29;
SELECT * FROM user_1 WHERE age BETWEEN 18 AND 29;
SELECT * FROM user_2 WHERE age BETWEEN 18 AND 29;
SELECT * FROM user_3 WHERE age BETWEEN 18 AND 29;
```

代码层合并（Java/Python/Go 都一样）

```php
结果集 = []
for 表名 in [user_0, user_1, user_2, user_3]:
    数据 = 查询(表名, age between 18 and 29)
    结果集.extend(数据)

结果集.sort(创建时间/ID)
返回 分页(结果集, pageNum, pageSize)
```

优点

- 零改造
- 最快上线

缺点

- 数据量大后性能差
- 分页很难精确（必须查全量再分页）

#### 代码示例

简单版（遍历所有分表 + 合并结果）

数据量不大、快速上线

```php
<?php
// 数据库配置
$pdo = new PDO("mysql:host=127.0.0.1;dbname=test;charset=utf8mb4", "root", "");

// 要查询的分表
$tables = ['user_0', 'user_1', 'user_2', 'user_3'];

// 范围条件
$minAge = 18;
$maxAge = 29;

$result = [];

// 遍历所有分表查询
foreach ($tables as $table) {
    $stmt = $pdo->prepare("SELECT * FROM {$table} WHERE age BETWEEN ? AND ?");
    $stmt->execute([$minAge, $maxAge]);
    $list = $stmt->fetchAll(PDO::FETCH_ASSOC);
    
    // 合并结果
    $result = array_merge($result, $list);
}

// 排序（可选）
array_sort($result, 'create_time', SORT_DESC);

// 输出最终结果
var_dump($result);

// 二维数组排序函数
function array_sort(&$array, $key, $sort = SORT_ASC) {
    $column = array_column($array, $key);
    array_multisort($column, $sort, $array);
}
?>
```

优点

- 0 改造表结构
- 5 分钟上线
- 代码简单易懂

缺点

数据量大后变慢（百万级以下没问题

### 方案 2：最优通用方案 → 建立**倒排索引表**（生产推荐）

核心思路

专门建一张**索引表**，把**年龄 → 用户 ID**映射存起来

```sql
user_age_index (
    age int,
    user_id bigint,
    primary key (age, user_id)
)
```

查询流程（18-29 岁）

1. **查索引表**：获取 18~29 岁所有 user_id
2. **路由分表**：根据 user_id 计算落在 user_0 ~ user_3 哪张表
3. **精确查询**：只查对应表，性能极高

优势

- 范围查询 = 索引查询 + 精准单表查询
- 性能接近不分表
- 支持分页、排序、count 精确计算

适合

90% 互联网公司分表场景的标准方案

####  代码示例

生产推荐（倒排索引表）

第 1 步：建索引表（只需执行一次）

```sql
CREATE TABLE user_age_index (
    age INT NOT NULL,
    user_id BIGINT NOT NULL,
    PRIMARY KEY (age, user_id),
    KEY idx_user_id (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

第 2 步：PHP 查询代码（性能极高）

```php
<?php
$pdo = new PDO("mysql:host=127.0.0.1;dbname=test;charset=utf8mb4", "root", "");

$minAge = 18;
$maxAge = 29;

// 1. 从索引表拿到符合年龄的 user_id
$stmt = $pdo->prepare("SELECT user_id FROM user_age_index WHERE age BETWEEN ? AND ?");
$stmt->execute([$minAge, $maxAge]);
$userIds = $stmt->fetchAll(PDO::FETCH_COLUMN, 0);

if (empty($userIds)) {
    echo "无数据";
    exit;
}

// 2. 根据 user_id 路由到对应的分表
$tableMap = [];
foreach ($userIds as $uid) {
    $tableIndex = $uid % 4;        // 你是 4 张分表
    $table = "user_$tableIndex";
    $tableMap[$table][] = $uid;
}

// 3. 批量查询每张表
$result = [];
foreach ($tableMap as $table => $uids) {
    $ids = implode(',', $uids);
    $stmt = $pdo->query("SELECT * FROM {$table} WHERE user_id IN ($ids)");
    $list = $stmt->fetchAll(PDO::FETCH_ASSOC);
    $result = array_merge($result, $list);
}

var_dump($result);
?>
```

优点

- **千万级数据也飞快**
- 支持分页、排序、count
- 生产标准方案

你必须加的索引（非常重要）

```sql
ALTER TABLE user_0 ADD INDEX idx_age(age);
ALTER TABLE user_1 ADD INDEX idx_age(age);
ALTER TABLE user_2 ADD INDEX idx_age(age);
ALTER TABLE user_3 ADD INDEX idx_age(age);
```

总结

- **小数据量** → 用方案 1（复制就能跑）
- **上线 / 正式项目** → 用方案 2（性能最好）
- 两套代码都是**PHP 原生、可直接部署**





### 方案 3：高性能方案 → 使用**ElasticSearch**

适用场景

- 大量范围查询（年龄、性别、城市、时间）
- 复杂筛选组合
- 大数据量（千万～亿级）

流程

1. 把 user 表数据同步到 ES
2. ES 做 `age:[18 TO 29]` 范围查询
3. 拿到 user_id 后回查分表获取详情

优点

- 极快的范围 / 多条件查询
- 天然支持分页、聚合、排序

缺点

- 增加中间件
- 有数据同步延迟

快速选型建议（直接照抄）

|   数据量    |     方案     | 难度 | 性能 |
| :---------: | :----------: | :--: | :--: |
|  < 100 万   | 全表扫描合并 | 极低 | 一般 |
| 100~1000 万 |  倒排索引表  |  中  | 优秀 |
|  > 1000 万  |  ES + 分表   |  高  | 顶级 |

关键坑点提醒（非常重要）

1. **不要在分表上直接跨表分页**（limit/offset）

   跨表分页必须**先查所有表 → 合并 → 内存排序 → 分页**

   

2. **必须给 age 字段加索引**

   每张 user 表都要建：

   ```sql
   CREATE INDEX idx_age ON user_0(age);
   ```

   

3. **范围查询不能用分片键优化**

   按 ID 哈希分表 = 任何非 ID 范围查询都必须查全部分表（或走索引表）

## 分表后如何分页查询

### 场景一: 想查询状态为 1 成功的订单分页

场景明确

条件：`status = 1`，4 张子表：`order_0、order_1、order_2、order_3`

**分片键 ≠ status**，所以无法路由单表，必须同时查 4 张表。

两种实现方案：**偏移分页（page/size 跳页）**、**游标分页（滚动加载推荐）**

> 统一前提：每张子表 `status` + 排序字段建立联合索引

```sql
-- 举例按创建时间倒序
INDEX idx_status_createtime (status, create_time desc, id)
```

#### 方案一：传统 offset 分页（支持跳页 page,size）

适用：后台管理系统，可以跳转到第 N 页；**缺点：深度分页性能差**

分页参数：page=2，size=10 → offset=(page-1)*size =10

步骤

1. 并行向 4 张表分别查询【满足条件、排序、limit offset, size】

> 业务逻辑可以循环查询四张表不用写四个sql

```sql
-- 每张表单独执行
SELECT id,order_no,create_time,status 
FROM order_0 
WHERE status = 1 
ORDER BY create_time DESC, id DESC
LIMIT 10,10;

SELECT id,order_no,create_time,status 
FROM order_1 
WHERE status = 1 
ORDER BY create_time DESC, id DESC
LIMIT 10,10;

order_2、order_3同理
```

2. 代码拿到 4 份结果集，**内存合并**

3. 整体再次按照 `create_time DESC, id DESC` 全局排序

4. 截取 `[offset, offset+size]` 作为当前页数据返回

统计总条数（前端展示总页数需要）

```php
SELECT COUNT(*) FROM order_0 WHERE status=1
UNION ALL
SELECT COUNT(*) FROM order_1 WHERE status=1
UNION ALL
SELECT COUNT(*) FROM order_2 WHERE status=1
UNION ALL
SELECT COUNT(*) FROM order_3 WHERE status=1
```

巨大痛点

page 越大灾难越明显：

比如 page=1000，offset=9990

每张表都要执行 `limit 9990,10`，数据库扫描大量数据，网络传输无用数据，内存压力暴涨。

✅ 业务约束：限制最大可查询页码，例如最多支持查询前 100 页。

不推荐写法（千万别用）

```sql
-- 错误示范！
(select * from order_0 where status=1)
UNION ALL
(select * from order_1 where status=1)
UNION ALL
(select * from order_2 where status=1)
UNION ALL
(select * from order_3 where status=1)
ORDER BY create_time desc
LIMIT 10,10;
```

逻辑问题：MySQL 会先把 4 张表所有符合条件数据全部汇总，再排序分页。表数据量大直接 OOM / 超时！

#### 方案二：游标分页【强烈推荐，生产首选】

适用：APP 下拉滚动、信息流；**无深度分页问题，代价：不能直接跳页**

思路：不使用 offset，传递上一页最后一条数据的排序值当做游标。

排序规则：`create_time DESC, id DESC`

游标字段：`last_create_time、last_id`

第一页（无游标）

每张表查询满足条件的数据，取 size 条

```sql
SELECT id,order_no,create_time
FROM order_0
WHERE status = 1
ORDER BY create_time DESC, id DESC
LIMIT 10;
-- order_1/2/3 相同SQL
```

下一页（携带游标参数）

```sql
SELECT id,order_no,create_time
FROM order_0
WHERE status = 1
AND ( create_time < #{last_ct} OR (create_time = #{last_ct} AND id < #{last_id}) )
ORDER BY create_time DESC, id DESC
LIMIT 10;
-- 四张表全部执行
```

再次合并排序取前 size 条；返回为空代表没有下一页。

优势：查询条件可以有效利用索引，无论翻多少页性能稳定。

### **全部分表遍历查询**

**（当前场景：按性别过滤，不知道数据在哪张表）**：必须把 4 张表分别查询，`unionAll`合并结果，**合并后的结果再关联其他表**（不能直接在每个子查询 join，性能差）

#### 1. **原生 Query Builder 代码示例（不用任何扩展包）**

缺点：unionAll 是**全表扫描所有分表**，数据量大的时候性能很差。 注意：**不能直接用 Eloquent 模型 with 关联**，因为 union 出来的是子查询，不是模型原生表，with 预加载会失效。

#### 封装unionall

```php
<?php

namespace App\Helpers;

use Illuminate\Support\Facades\DB;

class TableShardingHelper
{
    /**
     * 获取分表名列表
     */
    public static function getModTables(string $prefix, int $count): array
    {
        $tables = [];
        for ($i = 0; $i < $count; $i++) {
            $tables[] = $prefix . '_' . $i;
        }
        return $tables;
    }

    /**
     * 根据分片键算出对应表名 取模分片
     */
    public static function getModTable(string $prefix, int $shardingValue, int $count): string
    {
        $idx = $shardingValue % $count;
        return $prefix . '_' . $idx;
    }

    /**
     * 生成unionAll子查询，适用于【不带分片键，需要查全部分表】的场景
     * @param array $tables 全部分表名
     * @param callable $callback 回调，给QueryBuilder加where、select
     * @return \Illuminate\Database\Query\Builder
     */
    public static function buildUnionAllQuery(array $tables, callable $callback)
    {
        $queries = [];
        foreach ($tables as $table) {
            $q = DB::table($table);
            $callback($q);
            $queries[] = $q;
        }
        $unionQuery = array_shift($queries);
        foreach ($queries as $subQ) {
            $unionQuery = $unionQuery->unionAll($subQ);
        }
        return $unionQuery;
    }
}
```

使用示例

> 查询性别 = 1 男性，再关联 user_profile

```php

    $query->where('gender',1)
          ->select('id','nick_name','email','gender','created_at');
```
