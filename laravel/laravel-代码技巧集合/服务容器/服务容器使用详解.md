## 服务容器 (Service Container) 完整讲解 + 实战场景 + 详细代码

> Laravel 核心就是**服务容器**，本质：**依赖自动管理、解耦、控制反转 (IoC)、依赖注入 (DI)**
>
> 两个核心概念区分：
>
> 1. **IoC（控制反转）**：控制权交给容器，不再自己`new`对象
> 2. **DI（依赖注入）**：容器自动把依赖传给类，不需要手动实例化
> 3. **服务容器**：实现 IoC、DI 的工具

## 容器最常用 API 速览

```php
// 1.绑定 接口=>实现类
$this->app->bind(抽象, 实现);
// 2.单例绑定（全局只实例化一次）
$this->app->singleton(抽象, 实现);
// 3.实例绑定（直接绑定已经实例化好的对象）
$this->app->instance(名称, 对象);
// 4.从容器解析实例
$obj = $this->app->make(类名);
// 5.自动注入（构造器注入/方法注入，框架自动make）
```

> 所有绑定推荐写在 **`app/Providers/AppServiceProvider.php`** 的 `register()` 方法中
>
> ⚠️ 规则：`register()`只做绑定，不要调用`make()`；`boot()`中可以解析服务

###  场景 1：基础场景 bind—— 接口和实现解耦（业务最常用）

需求

项目需要发送通知，支持「短信通知」「邮件通知」，后续可能新增企业微信、钉钉推送。

**坏方案**：业务代码直接`new SmsNotify()`；新增渠道需要到处改代码。

**容器方案**：面向接口编程，容器绑定接口对应实现，切换实现无需修改业务代码。

步骤 1：创建通知接口

`app/Contracts/NotifyInterface.php`

```php
<?php

namespace App\Contracts;

interface NotifyInterface
{
    /**
     * 发送通知
     * @param string $mobile 接收人
     * @param string $content 消息内容
     * @return bool
     */
    public function send(string $mobile, string $content): bool;
}
```

步骤 2：创建接口实现类

短信实现 `app/Services/SmsNotify.php`

```php
<?php

namespace App\Services;
use App\Contracts\NotifyInterface;

class SmsNotify implements NotifyInterface
{
    // 模拟短信发送
    public function send(string $mobile, string $content): bool
    {
        echo "【短信】发送至{$mobile}：{$content}" . PHP_EOL;
        return true;
    }
}
```

邮件实现 `app/Services/EmailNotify.php`

```php
<?php

namespace App\Services;
use App\Contracts\NotifyInterface;

class EmailNotify implements NotifyInterface
{
    public function send(string $mobile, string $content): bool
    {
        echo "【邮件】发送至{$mobile}：{$content}" . PHP_EOL;
        return true;
    }
}
```

步骤 3：在服务提供者绑定接口与实现

`app/Providers/AppServiceProvider.php`

```php
<?php

namespace App\Providers;

use App\Contracts\NotifyInterface;
use App\Services\SmsNotify;
use Illuminate\Support\ServiceProvider;

class AppServiceProvider extends ServiceProvider
{
    public function register()
    {
        // 绑定：接口 => 具体实现
        // 现在解析NotifyInterface会得到SmsNotify实例
        $this->app->bind(NotifyInterface::class, SmsNotify::class);

        // 如果后续想全局切换为邮件通知，只需要修改这里！业务代码一行不动
        // $this->app->bind(NotifyInterface::class, EmailNotify::class);
    }

    public function boot()
    {
        //
    }
}
```

步骤 4：业务中使用（两种方式）

方式 A：控制器构造器自动注入（推荐，框架自动从容器解析）

`app/Http/Controllers/NotifyController.php`

```php
<?php

namespace App\Http\Controllers;

use App\Contracts\NotifyInterface;
use Illuminate\Http\Request;

class NotifyController extends Controller
{
    // 容器自动解析NotifyInterface，注入SmsNotify实例
    public function __construct(
        protected NotifyInterface $notifyService
    ) {}

    public function send(Request $request)
    {
        $this->notifyService->send('13800138000', '您有一条系统消息');
    }
}
```

方式 B：手动 make 解析

```php
// 任意地方（命令、控制器、事件）
$notify = app()->make(NotifyInterface::class);
$notify->send('13800138000', '测试消息');
```

优势

以后新增钉钉通知，只需要：

1. 新建 `DingNotify` 实现 `NotifyInterface`
2. 修改 `AppServiceProvider` 绑定，**所有业务代码完全不用改动**，完美符合开闭原则。

###  场景 2：带构造参数依赖的绑定（工厂闭包绑定）

需求

短信服务需要传入第三方 api key、secret（动态参数），无法直接简单绑定类名，使用**闭包绑定**。

修改短信服务，增加构造依赖：

```php
<?php
namespace App\Services;
use App\Contracts\NotifyInterface;

class SmsNotify implements NotifyInterface
{
    public function __construct(
        protected string $apiKey,
        protected string $apiSecret
    ) {}

    public function send(string $mobile, string $content): bool
    {
        echo "【短信】key:{$this->apiKey} 发送{$mobile}:{$content}" . PHP_EOL;
        return true;
    }
}
```

AppServiceProvider 闭包绑定

```php
public function register()
{
    $this->app->bind(NotifyInterface::class, function ($app) {
        // 闭包内可以读取配置，动态实例化对象
        $key = config('sms.api_key');
        $secret = config('sms.api_secret');
        return new \App\Services\SmsNotify($key, $secret);
    });
}
```

> 容器执行`make(NotifyInterface)`时，自动执行闭包拿到实例。

### 场景 3：singleton 单例绑定（高频场景）

区别

- `bind()`：每次`make()`都会创建**全新对象**
- `singleton()`：第一次创建，之后全部复用同一个实例（单例）

```php
public function register()
{
    // 全局单例，整个生命周期只new一次
    $this->app->singleton(NotifyInterface::class, function ($app) {
        $key = config('sms.api_key');
        $secret = config('sms.api_secret');
        return new \App\Services\SmsNotify($key, $secret);
    });
}
```

适用场景：客户端 SDK、Redis 连接、第三方 http 客户端，不需要重复创建。

### 场景 4：instance () 绑定已有实例

如果你已经实例化对象，直接存入容器：

```php
public function register()
{
    $sms = new \App\Services\SmsNotify('key123','secret456');
    // 直接把现成对象放进容器，永远返回这个对象
    $this->app->instance(NotifyInterface::class, $sms);
}
```

### 场景 5：依赖嵌套自动注入（容器强大特性）

容器会**递归解析所有依赖**，不需要手动层层 new。

示例：

```php
// 日志服务
class LogService
{

}

// 通知服务依赖日志
class SmsNotify implements NotifyInterface
{
    public function __construct(
        protected LogService $log
    ){}
    // ...
}
```

只需要正常绑定`NotifyInterface`，容器自动识别`SmsNotify`依赖`LogService`，自动`new LogService`注入！

> 你完全不用关心内部依赖，这是容器最大价值。

### 场景 6：方法注入（不仅仅构造器注入）

Laravel 除了构造器注入，控制器方法同样支持自动注入

```php
public function send(Request $request, NotifyInterface $notify)
{
    $notify->send('1380000000','消息');
}
```

访问路由时框架自动解析`NotifyInterface`传入方法。

### 场景 7：上下文绑定（高级：同一个接口，不同地方解析不同实现）

业务场景举例

订单模块用短信通知，会员模块用邮件通知，**同一个接口，不同场景不同实现**。

```php
public function register()
{
    $this->app->when(\App\Http\Controllers\OrderController::class)
        ->needs(NotifyInterface::class)
        ->give(\App\Services\SmsNotify::class);

    $this->app->when(\App\Http\Controllers\MemberController::class)
        ->needs(NotifyInterface::class)
        ->give(\App\Services\EmailNotify::class);
}
```

- OrderController 注入 Notify → 短信
- MemberController 注入 Notify → 邮件

### 场景 8：自定义 Facade 底层原理（容器实例）

Facade 本质就是从容器取服务。

```php
// Facade源码简化逻辑
protected static function getFacadeAccessor()
{
    return NotifyInterface::class;
}
// 内部最终调用 app()->make()
```

### 场景 9：命令行、事件监听器内使用容器注入

任务 / 命令同样支持构造器注入，和控制器一致：

```php
class SendNotifyCommand extends Command
{
    protected $signature = 'notify:send';

    public function __construct(
        protected NotifyInterface $notify
    )
    {
        parent::__construct();
    }

    public function handle()
    {
        $this->notify->send('13800','定时消息');
    }
}
```

## 常见面试重点坑点

1. **register () 不能 make 服务**

```php
// ❌错误！register阶段容器还未全部加载，容易依赖顺序报错
public function register(){
    $test = $this->app->make(NotifyInterface::class);
}
// ✅ 如需解析实例放到boot()
public function boot(){
    $test = $this->app->make(NotifyInterface::class);
}
```

1. 自动注入**只能解析类 / 接口**，不能直接注入普通字符串参数（普通参数要用闭包绑定）
2. 什么时候用 bind、什么时候 singleton？

- 无状态服务、轻量类：bind
- SDK、连接池、http 客户端、重量级对象：singleton

1. `app()` 助手函数就是获取全局容器实例，等同于 `$this->app`（服务提供者内）

## 真实项目通用规范模板

1. 契约 (接口) 统一放在 `app/Contracts/`
2. 业务实现类放在 `app/Services/`
3. 全部绑定统一集中写在 `AppServiceProvider`
4. 控制器、命令、事件统一使用构造注入，禁止到处`new XXX()`
