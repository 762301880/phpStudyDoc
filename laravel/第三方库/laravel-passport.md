## 什么是OAuth2

###  OAuth2 不是登录！它是【授权协议】

举个生活例子：

> 你去打印店，想打印你微信里的照片。 打印店**不能要你的微信账号密码**（绝对不能给密码！）。 微信弹出页面：「是否允许打印店读取你的相册？」 你点同意 → 微信发给打印店一张**临时通行证（access_token）** 打印店拿着通行证，就可以拿你的照片。打印店永远不知道你的微信密码。

这就是 OAuth2。

👉核心思想： **不把密码交给第三方，而是发一张临时通行证，允许第三方有限度调用接口。

### OAuth2 里 4 个角色（记住这 4 个人）

1. **资源所有者 (用户)**：就是你本人
2. **客户端 (第三方应用)**：打印店 / 别的平台，想拿数据
3. **授权服务器**：微信，负责发通行证 token
4. **资源服务器**：微信存放照片的接口，校验通行证能不能用

### OAuth2 有 4 种模式（4 种干活方式），非常关键

OAuth2 一共 4 种授权方式，**分别应对 4 种完全不同场景**

#### ① Authorization Code 授权码模式（最常见）

场景：**网页登录，第三方网站用微信登录** 流程：

1. 跳到微信页面，你扫码登录
2. 微信返回一个临时授权码
3. 第三方拿着授权码，去换 access_token（通行证）
4. 拿着 token 调用接口拿你的用户信息

#### ② Implicit 简化模式

基本淘汰，浏览器前端用，不安全，忽略。

#### ③ Password 密码模式

第三方直接拿你的账号密码，换取 token。 **不推荐对外使用，只适合自家 APP。**

#### ④ Client Credentials 客户端凭据模式

重点！！【两条腿 OAuth，没有用户！】

场景：**服务器 ↔ 服务器。机器调用机器，全程没有人。**

例子：

- A 电商平台，调用 B 物流平台的接口，去打印快递单。
- 两边都是后端程序，**没有任何用户扫码、没有任何人点击同意**。

流程：

1. B 平台（你）给 A（第三方）一对账号：`client_id`、`client_secret`
2. A 拿着这两个凭证，**单独发一次请求**，换取一张临时通行证 `access_token`
3. A 再拿着这张通行证，去调用业务接口

> 这里没有「人」参与，不需要登录任何账号。 这就是 Laravel‑Passport 的 `client_credentials`。

## OAuth2 使用场景

OAuth2 核心定位：**授权协议，不是登录协议**。 解决一件事：**A 系统，在不拿到你的账号密码的前提下，有限访问你在 B 系统的数据**。

### 实际场景:网页qq登录

**网页 QQ 登录（QQ 互联）就是 OAuth2.0，用的是【授权码模式 Authorization‑Code】**QQ互联W...

完整流程（大白话）

1. 你在网站点「QQ 登录」，网页跳转到腾讯的授权页面
2. 你扫码 / 输密码登录 QQ，然后点 **同意授权**
3. 腾讯跳转回你的网站回调地址，URL 带上一个临时字符串：`code`（授权码）
4. **你的网站后端拿着这个 code + app_id + app_secret，再请求腾讯接口**，换到 `access_token`（通行证）
5. 拿着 access_token，调用腾讯接口拿到你的头像、昵称，完成登录

> 关键点：你的网站**永远拿不到你的 QQ 密码**，这正是 OAuth2 设计的初衷。

区分一个很容易混淆的知识点

1. **QQ 登录、微信扫码登录、Github 登录** → OAuth2 **授权码模式（有人参与）**
2. **A 平台后端调用 B 平台后端接口（机器‑机器）** → OAuth2 **client_credentials 客户端凭据模式（没有人）**

##  安装

**php7.4**

坚持用 PHP7.4，安装能适配 Passport 最高兼容版本 v10.3.3

> v10.3.3 是**PHP7.4 能跑的最后一个 passport 版本** 但是这里还有 `psr/http-message 2.0` 的坑，需要带上 `-W` 参数让 composer 降级它：

```php
composer require laravel/passport:10.3.3 -W
```
