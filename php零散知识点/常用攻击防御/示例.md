##  场景: 官网攻击者不停随机切换参数,ip,打满php-fpm

公开匿名例如门店接口防御（无需登录、不能弹窗验证码、不能强制登录）

现状复盘：

- 完全公开接口，**所有访问都是匿名，不能登录、不能弹验证码破坏普通用户体验**
- 攻击者代理池，IP 每请求都变，裸 HTTP 脚本，疯狂遍历随机查询参数组合
- 伤害来源不是 QPS 高，是**海量不同查询条件，生成大量不同 SQL，打满 MySQL CPU**
- 不能把真实访客拦死，官网普通游客可以正常查门店

> 核心结论：**这种场景做不到 100% 拦截请求，但可以做到：就算请求源源不断进来，数据库不会崩，网站不会卡死。** 不要追求识别坏人，重点：**限制查询的破坏力 + 全局接口降级 + 约束 SQL 代价**。

**关键现实约束**

1. ❌ 不能强制登录
2. ❌ 不能随便弹人机验证 / 图片验证码（普通游客访问会中招，体验灾难）
3. ❌ IP 限流基本报废
4. ❌ Session/token 做身份不可靠，攻击者可以随便带 Cookie
5. ✅ 允许正常游客多条件筛选
6. ✅ 攻击来的时候，优先保证网站整体可用，可以**适度阉割门店列表接口能力，不能让整个官网挂**
