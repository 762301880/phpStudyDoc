## 签名主要防什么

> **核心作用是防止爬虫**

### 场景 1：未登录用户填手机号表单（留资 / 注册）

不加防护，脚本可以：

- 疯狂提交假手机号，把你的数据库塞满垃圾数据
- 拿真实手机号做短信轰炸（如果发短信验证码的话）
- 把你的短信费用刷爆

签名 + 验证码 + 频率限制，就是为了挡这种。

### 场景 2：未登录查商品列表

不加防护，脚本可以：

- 高频轮询你的商品接口，把服务器 CPU / 带宽打满
- 把你整个商品库爬走（竞品扒价）
- 爬虫绕过敏感分页，抓全量数据

## 签名缺点

### 签名 ≠ 万能防护(懂技术的人可逆向写pyton脚本)

**前端加签（像酷狗那种盐写在 JS 里），只能防 "完全不懂技术、直接 Postman 裸调" 的人。**

懂行的人：

1. 打开你网页 F12
2. 把 JS 里的签名函数扒出来
3. 自己用 Python 复刻一遍
4. 照样批量请求你的接口

## 真正防住脚本攻击的完整方案

| 层级                  | 手段                                 | 防什么                        |
| --------------------- | ------------------------------------ | ----------------------------- |
| **第一层：前端加签**  | 参数排序 + 盐 + MD5（酷狗这种）      | 防 Postman 裸调，提高脚本门槛 |
| **第二层：验证码**    | 图形验证码 / 滑块 / 点选             | 防自动化脚本，必须有人参与    |
| **第三层：频率限制**  | 同一个 IP / 手机号 1 分钟只能发 5 次 | 防重放、防批量刷              |
| **第四层：行为风控**  | 检测请求间隔、鼠标轨迹、设备指纹     | 防高级模拟真人行为的脚本      |
| **第五层：WAF / CDN** | 云厂商的 Web 应用防火墙              | 挡 DDoS、恶意 IP              |
| **第六层：接口降级**  | 高峰期直接返回缓存 / 静态页          | 服务器扛不住时保命            |



## 加签代码示例

### 整体设计思路

```html
前端发请求时：
  1. 收集所有业务参数
  2. 自动加 timestamp（当前时间戳）+ nonce（随机串）
  3. 把所有参数按 key 字典序排序
  4. 拼成 key1=value1&key2=value2...
  5. 头尾拼上密钥 salt
  6. MD5 得到 sign
  7. 把 sign 放到请求头里发出去

后端收请求时（中间件）：
  1. 取出所有参数 + timestamp + nonce + sign
  2. 检查 timestamp 是否在 5 分钟内（防重放）
  3. 检查 nonce 是否用过（Redis 存，防重放）
  4. 用同样的算法重算 sign
  5. 和前端传来的 sign 比对，不一致就拒绝
```

### 前端 Vue 示例（axios 拦截器）

```js
// src/utils/signRequest.js
import axios from 'axios'
import CryptoJS from 'crypto-js'  // npm install crypto-js

// ==================== 配置区 ====================
// 注意：公开接口的密钥必然会暴露在前端 JS 里，这里只是提高脚本门槛
// 真正的高安全场景要用非对称加密（前端用公钥加密，后端用私钥解密验签）
const APP_KEY = 'your-secret-key-here-32bytes'  // 前后端共享的密钥，长度建议 32 位以上
const TIMESTAMP_EXPIRE = 300  // 签名有效期 300 秒（5分钟）
// ==============================================

// 生成随机 nonce（防重放，每次请求唯一）
function generateNonce() {
  return Math.random().toString(36).substring(2) + Date.now().toString(36)
}

// 核心：计算签名
function calcSign(params, timestamp, nonce) {
  // 1. 把所有参数合并（业务参数 + timestamp + nonce）
  const allParams = { ...params, timestamp, nonce }

  // 2. 按 key 的 ASCII 字典序排序
  const sortedKeys = Object.keys(allParams).sort()

  // 3. 拼成 key1=value1&key2=value2...（注意：sign 本身不参与签名）
  const str = sortedKeys
    .filter(key => key !== 'sign')
    .map(key => `${key}=${allParams[key]}`)
    .join('&')

  // 4. 头尾拼上密钥，做 MD5
  const raw = APP_KEY + str + APP_KEY
  return CryptoJS.MD5(raw).toString()
}

// 创建 axios 实例
const request = axios.create({
  baseURL: 'shturl.cc/WjYqSUexQLpDaO4ZY',
  timeout: 10000,
})

// 请求拦截器：自动加签名
request.interceptors.request.use(config => {
  const timestamp = Math.floor(Date.now() / 1000)  // 秒级时间戳
  const nonce = generateNonce()

  // 从 config 里取出业务参数（GET 是 params，POST 是 data）
  const businessParams = config.method === 'get'
    ? (config.params || {})
    : (config.data || {})

  // 计算签名
  const sign = calcSign(businessParams, timestamp, nonce)

  // 把签名相关的信息放到请求头（不污染业务参数）
  config.headers['X-Timestamp'] = timestamp
  config.headers['X-Nonce'] = nonce
  config.headers['X-Sign'] = sign

  return config
}, error => {
  return Promise.reject(error)
})

// 响应拦截器：统一处理验签失败
request.interceptors.response.use(
  response => response,
  error => {
    if (error.response && error.response.status === 401) {
      console.error('签名校验失败：', error.response.data)
      alert('请求被拒绝，可能是签名过期或参数被篡改')
    }
    return Promise.reject(error)
  }
)

export default request

```

### 后端 Laravel 示例（中间件验签）

**创建中间件**

```php
php artisan make:middleware VerifyApiSign
```

**中间件逻辑**

```php
// app/Http/Middleware/VerifyApiSign.php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Cache;  // 用 Redis 存 nonce 防重放

class VerifyApiSign
{
    // 和前端一致的密钥
    private const APP_KEY = 'your-secret-key-here-32bytes';
    private const TIMESTAMP_EXPIRE = 300; // 5 分钟有效期

    public function handle(Request $request, Closure $next)
    {
        // 1. 从请求头取出前端传来的签名信息
        $timestamp = $request->header('X-Timestamp');
        $nonce     = $request->header('X-Nonce');
        $sign      = $request->header('X-Sign');

        // 缺了任何一个都直接拒绝
        if (!$timestamp || !$nonce || !$sign) {
            return response()->json([
                'code' => 401,
                'msg'  => '缺少签名参数',
            ], 401);
        }

        // 2. 检查时间戳是否在有效期内（防重放：请求不能太旧）
        if (abs(time() - (int)$timestamp) > self::TIMESTAMP_EXPIRE) {
            return response()->json([
                'code' => 401,
                'msg'  => '请求已过期，请重试',
            ], 401);
        }

        // 3. 检查 nonce 是否用过（防重放：同一个随机数不能用第二次）
        //    用 Redis 存，key 是 nonce，有效期和签名一样 5 分钟
        if (Cache::has('nonce:' . $nonce)) {
            return response()->json([
                'code' => 401,
                'msg'  => '重复请求',
            ], 401);
        }
        Cache::put('nonce:' . $nonce, 1, self::TIMESTAMP_EXPIRE);

        // 4. 取出所有业务参数（GET 和 POST 都取）
        $params = array_merge(
            $request->query(),      // GET 参数
            $request->post()        // POST 参数
        );

        // 5. 和前端一样的算法重算签名
        $calcSign = $this->calcSign($params, $timestamp, $nonce);

        // 6. 比对签名（用 hash_equals 防时序攻击）
        if (!hash_equals($calcSign, $sign)) {
            return response()->json([
                'code' => 401,
                'msg'  => '签名校验失败',
            ], 401);
        }

        // 验签通过，继续处理请求
        return $next($request);
    }

    /**
     * 和前端 calcSign 完全一致的算法
     */
    private function calcSign(array $params, string $timestamp, string $nonce): string
    {
        // 1. 合并参数（注意：sign 本身不参与签名）
        $allParams = array_merge($params, [
            'timestamp' => $timestamp,
            'nonce'     => $nonce,
        ]);
        unset($allParams['sign']);

        // 2. 按 key 的 ASCII 字典序排序
        ksort($allParams);

        // 3. 拼成 key1=value1&key2=value2...
        $str = [];
        foreach ($allParams as $key => $value) {
            // 数组/对象类型要 JSON 编码（和前端一致）
            if (is_array($value)) {
                $value = json_encode($value, JSON_UNESCAPED_UNICODE);
            }
            $str[] = "{$key}={$value}";
        }
        $str = implode('&', $str);

        // 4. 头尾拼密钥，MD5
        return md5(self::APP_KEY . $str . self::APP_KEY);
    }
}
```

**注册中间件**

```php

    // ... 其他中间件
    'verify.sign' => \App\Http\Middleware\VerifyApiSign::class,
];
```

**给路由加上中间件**

```php

// 公开的商品列表接口，加上签名校验

```

### 关键注意事项

#### 1. 密钥安全问题

公开接口的密钥**必然暴露在前端 JS 里**，这套方案只能防 "直接裸调接口的脚本"，防不住懂行的人扒 JS。如果真要高安全：

- 用 RSA 非对称加密：前端用公钥加密参数，后端用私钥验签
- 或者密钥定期换 + 加验证码 + 限流

#### 2. nonce 防重放依赖 Redis

一定要开 Redis 缓存，否则 nonce 存不了，防重放就失效了。

#### 3. timestamp 有效期别太长

5 分钟够了，太长会给重放攻击留窗口。

#### 4. 配合其他防护

签名只是第一道，建议同时加：

- **接口限流**（Laravel 自带 `throttle` 中间件）
- **验证码**（敏感操作必须加）
- **CDN 缓存**（商品列表这种读多写少的接口，直接缓存，根本不打 PHP）

####  5.和酷狗那套的区别

> [酷狗签名研究地址](https://t1.kugou.com/6Veh567G5V2)

| 酷狗那套                     | 你这套                     |
| ---------------------------- | -------------------------- |
| 没有 timestamp，请求永远有效 | 有 timestamp，5 分钟过期   |
| 没有 nonce，抓包可以重放     | 有 nonce，用一次就作废     |
| 参数直接拼在 URL 里          | 签名放请求头，不污染 URL   |
| 没有限流                     | 配合 Laravel throttle 限流 |
