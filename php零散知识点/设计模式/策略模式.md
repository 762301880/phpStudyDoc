## 策略模式核心

**定义一族算法，把每个算法封装成独立类，让它们可以互相替换，算法变化不影响调用方**。

在 Laravel 里适合场景：支付渠道、订单折扣、文件上传驱动、消息推送（短信 / 邮件 / 企业微信）等。

## 示例场景：**订单折扣策略**

- 普通会员：无折扣

- VIP 会员：9 折

- SVIP 会员：8 折

###  1. 先定义策略接口（统一规范）

`app/Contracts/DiscountStrategy.php`

```php
<?php

namespace App\Contracts;

/**
 * 折扣策略接口
 * 所有折扣策略必须实现这个方法，保证调用方统一调用入口
 */
interface DiscountStrategy
{
    /**
     * 计算折扣后价格
     * @param float $originalPrice 原价
     * @return float 折扣后价格
     */
    public function calc(float $originalPrice): float;
}
```

### 2. 各个具体策略实现类

####  普通会员策略

 `app/Services/Discount/CommonMemberStrategy.php`

```php
<?php

namespace App\Services\Discount;

use App\Contracts\DiscountStrategy;

/**
 * 普通会员 - 无折扣策略
 */
class CommonMemberStrategy implements DiscountStrategy
{
    public function calc(float $originalPrice): float
    {
        // 原价返回，不打折
        return $originalPrice;
    }
}
```

####   VIP 会员策略

`app/Services/Discount/VipMemberStrategy.php`

```php
<?php

namespace App\Services\Discount;

use App\Contracts\DiscountStrategy;

/**
 * VIP会员 9折策略
 */
class VipMemberStrategy implements DiscountStrategy
{
    public function calc(float $originalPrice): float
    {
        // 9折 = 原价 * 0.9
        return round($originalPrice * 0.9, 2);
    }
}
```

#### SVIP 会员策略

`app/Services/Discount/SvipMemberStrategy.php`

```php
<?php

namespace App\Services\Discount;

use App\Contracts\DiscountStrategy;

/**
 * SVIP会员 8折策略
 */
class SvipMemberStrategy implements DiscountStrategy
{
    public function calc(float $originalPrice): float
    {
        // 8折
        return round($originalPrice * 0.8, 2);
    }
}
```

### 3. 上下文 Context 类（策略管理器，对外统一入口）

Context 作用：持有策略对象，对外暴露统一方法，客户端只和 Context 打交道，不用直接操作策略类

`app/Services/Discount/DiscountContext.php`

```php
<?php

namespace App\Services\Discount;

use App\Contracts\DiscountStrategy;

/**
 * 折扣上下文类（策略容器）
 * 客户端调用的入口，负责切换不同的折扣策略
 */
class DiscountContext
{
    // 保存当前选中的策略实例
    protected DiscountStrategy $strategy;

    /**
     * 构造函数，可以注入初始策略
     * @param DiscountStrategy $strategy
     */
    public function __construct(DiscountStrategy $strategy)
    {
        $this->strategy = $strategy;
    }

    /**
     * 动态切换策略
     * @param DiscountStrategy $strategy
     * @return void
     */
    public function setStrategy(DiscountStrategy $strategy): void
    {
        $this->strategy = $strategy;
    }

    /**
     * 执行折扣计算，对外暴露方法
     * @param float $originalPrice
     * @return float
     */
    public function getPrice(float $originalPrice): float
    {
        return $this->strategy->calc($originalPrice);
    }
}
```

### 4.  Laravel Controller 调用示例

`app/Http/Controllers/OrderController.php`

```php
<?php

namespace App\Http\Controllers;

use App\Services\Discount\CommonMemberStrategy;
use App\Services\Discount\DiscountContext;
use App\Services\Discount\SvipMemberStrategy;
use App\Services\Discount\VipMemberStrategy;
use Illuminate\Http\Request;

class OrderController extends Controller
{
    /**
     * 测试策略模式 - 计算订单价格
     */
    public function testDiscount(Request $request)
    {
        // 订单原价
        $originalPrice = 100;

        // 模拟前端传入会员类型 common / vip / svip
        $memberType = $request->get('type', 'common');

        // 实例化上下文
        $context = new DiscountContext(new CommonMemberStrategy());

        // 根据会员类型，动态选择策略
        switch ($memberType) {
            case 'vip':
                $context->setStrategy(new VipMemberStrategy());
                break;
            case 'svip':
                $context->setStrategy(new SvipMemberStrategy());
                break;
            default:
                $context->setStrategy(new CommonMemberStrategy());
                break;
        }

        // 统一调用计算价格，客户端不需要关心底层是哪个策略
        $finalPrice = $context->getPrice($originalPrice);

        return response()->json([
            '原价' => $originalPrice,
            '会员类型' => $memberType,
            '折后价' => $finalPrice
        ]);
    }
}
```

### 6. 进阶优化：Laravel 容器自动解析 + 策略工厂（推荐实战写法）

上面 switch 判断可以封装成**工厂类**，消除大量 switch，大型项目推荐。

`app/Services/Discount/DiscountFactory.php`

```php
<?php

namespace App\Services\Discount;

use App\Contracts\DiscountStrategy;
use InvalidArgumentException;

/**
 * 折扣策略工厂：根据标识返回对应策略实例
 * 消除大量switch case，新增策略只需要新增类 + 注册到数组
 */
class DiscountFactory
{
    /**
     * 策略映射表 key:标识，value:策略类名
     * @var array
     */
    protected array $strategyMap = [
        'common' => CommonMemberStrategy::class,
        'vip'    => VipMemberStrategy::class,
        'svip'   => SvipMemberStrategy::class,
    ];

    /**
     * 根据会员类型获取策略实例
     * @param string $type
     * @return DiscountStrategy
     */
    public function make(string $type): DiscountStrategy
    {
        if (!isset($this->strategyMap[$type])) {
            throw new InvalidArgumentException("不存在该折扣策略：{$type}");
        }
        // laravel容器自动实例化，支持依赖注入
        return app($this->strategyMap[$type]);
    }
}
```

改造控制器调用方式：

```php
public function testDiscount(Request $request, DiscountFactory $factory)
{
    $originalPrice = 100;
    $memberType = $request->get('type', 'common');

    // 工厂获取策略
    $strategy = $factory->make($memberType);
    $context = new DiscountContext($strategy);
    $finalPrice = $context->getPrice($originalPrice);

    return response()->json([
        '原价' => $originalPrice,
        '会员类型' => $memberType,
        '折后价' => $finalPrice
    ]);
}
```

## 策略模式优点

1. **开闭原则**：新增策略（比如黑卡会员），只新增策略类，不用修改原有业务代码
2. **消除大量 if/switch**，业务逻辑拆分清晰
3. 策略独立，单元测试方便，可以单独测试每个折扣算法

## 适用场景

✅ 同一业务有多种可互换算法 / 规则（支付、折扣、导出、推送）

❌ 策略极少、几乎不会扩展的场景没必要上策略模式，会增加类文件
