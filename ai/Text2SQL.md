## 什么是 Text2SQL

**Text2SQL = Text to SQL**，简单说：**把自然语言（人话）自动转换成 SQL 查询语句**，属于大模型数据库领域非常经典的任务。

> 一句话总结：你用中文提问数据库，AI 帮你写出可执行的 SQL。

## 它是干嘛的？

举个例子，假设 MySQL 里有一张订单表 `order`（字段：id、user_name、amount、create_time、status）

- 你说：**帮我查 2026 年 10 月总金额大于 1000 的订单有多少条**
- Text2SQL 模型自动输出：

```sql
SELECT COUNT(*) FROM `order` 
WHERE create_time >= '2026-10-01' AND create_time < '2026-11-01' AND amount > 1000;
```

### 核心价值

1. **降低使用门槛**：不会写 SQL 的业务、产品、运营，直接用中文查数，不用找开发、数仓写查询
2. **自助数据分析**：BI 平台、数据中台内嵌，自然语言问答查库
3. RAG + Text2SQL 组合（你做 RAG 很容易碰到）
   - RAG：查非结构化文档（PDF、markdown）
   - Text2SQL：查结构化数据库（MySQL、PostgreSQL） 很多企业知识库是**混合检索：文档 RAG + 数据库 Text2SQL**

## Text2SQL 工作流程（简化版）

1. 拿到用户自然语言问题
2. 拿到数据库元信息：表名、字段名、字段类型、表注释、表关联关系（Schema）
3. 大模型理解问题 + 读懂表结构，生成 SQL
4. 【可选】校验 SQL 语法、做 SQL 纠错、过滤危险操作（`DROP`/`DELETE`）
5. 执行 SQL，返回结果给用户

## 常见局限（重点，生产踩坑点）

- 容易**幻觉**：看错字段、表名、关联条件，写出能跑但是结果错的 SQL
- 依赖准确的 Schema 信息，表注释写得差，效果暴跌
- 安全风险：必须拦截删表、改数据、全表扫描等高危 SQL
- 复杂多表关联、子查询、窗口函数很容易翻车

## 和普通 RAG 的区别

- RAG：检索**文档内容**，直接回答；数据是非结构化
- Text2SQL：检索**数据库结构**，生成 SQL 去库里查结构化数据
