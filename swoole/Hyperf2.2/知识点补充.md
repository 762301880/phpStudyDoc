## [worker_num 作用通俗解释](https://hyperf.wiki/3.0/#/zh-cn/config?id=serverphp-%e9%85%8d%e7%bd%ae%e8%af%b4%e6%98%8e)

Swoole 是多进程模型：

- Master 进程：监听端口、管理网络
- Manager 进程：管理 Worker 进程，进程挂了自动重启
- **Worker 进程：真正跑你的 PHP 业务代码（接口、逻辑、数据库查询）**

> `worker_num` 就是配置有多少个 Worker。

**举个例子**

```php
'worker_num' => swoole_cpu_num()
```

假设服务器是 4 核 8 线程，swoole_cpu_num () 得到 8，就会**创建 8 个 Worker 进程**。

每一个请求，会被分配到其中一个 Worker 进程去执行代码。

⚠️ **重点：一个 Worker 同一时间只能处理 1 个请求**

> Worker 是同步阻塞模式（默认），在处理 A 请求时，新来的 B 请求只能排队等这个 Worker 空闲。

### 设置这个参数有什么用？

#### **决定并发处理能力上限**

8 个 Worker，理论上最多同时处理 8 个请求。

- 如果并发 > worker_num：请求排队，响应变慢
- worker_num 太少：CPU 多核完全闲置，服务器性能浪费
- worker_num 太多：进程太多，操作系统频繁切换进程，CPU 开销变大，性能反而下降

#### **充分利用多核 CPU**

PHP 普通 fpm 或者原生 PHP 单脚本只能用 1 个 CPU 核心。

Swoole 开多个 Worker，**多个进程跑在不同 CPU 核上，同时干活**，这就是 Swoole 高性能的核心原因之一。

### 如何根据服务器配置设置多少worker

Swoole worker_num 配置公式（兼顾 CPU + 内存，生产可用）

> 前提：`worker_num` 是业务工作进程，**Task 进程单独算，不占用这个名额**

公式一：基础上限（CPU 维度）

```bash
CPU最大推荐worker = 逻辑CPU核数 × 系数
```

CPU 密集型（大量计算、图片处理、加密）：系数 = **1**

IO 密集型（查 MySQL/Redis、HTTP 调用，绝大多数 web 接口）：系数 = **2 ~ 3**

> 不建议系数 >4，上下文切换会爆炸

套入你的机器：2 核 2G，Laravel/ThinkPHP

1. CPU 上限：逻辑核 = 2，IO 密集，2 × 2 = 4
2. 内存上限：剩余约 1G，单 worker≈100MB → 10
3. `min(4, 10)` → worker_num = 4

> 如果发现内存经常飘高，降到 2
